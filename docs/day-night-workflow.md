# 白天定方向，晚上执行

[Notion 决策入口](https://app.notion.com/p/3db3285284df811897cfc48b24565164) · [调研队列](https://app.notion.com/p/aa5da2753776477390337fe3fa25d8bd) · [研究卡](product-research-backlog.md) · [Git 执行主线](../.claude/autopilot/mainline.md)

这是项目协作约定。夜间唤醒由 Codex 本任务的定时跟进负责；Task Router 自身尚未实现完整自主分级、多执行器路由或自动业务验收。

## 白天只做一个选择

在 Notion 队列选择一张卡，将状态改为 **已选·待执行**，勾选 **白天已确认**，核对本轮问题和交付标准。也可以在当前 Codex 任务明确说“今晚做 R1，按卡片验收”，由助手记录这次选择。

同一晚只接受一个任务。默认最多 60 分钟、额外付费 0 元；时间上限是执行约定，不是已实现的 token 硬预算。卡片初始值不代表已经授权执行，助手不能自己勾选确认或把推荐当决定。若要求继续先前未完任务，白天重新将其标为已选并确认范围。

## 两处记录如何配合

- **Notion 是决策入口**：候选、白天选择、当前结果和下一条待决定问题。只在该项目队列读写，保留用户新改动。
- **Git 主线是接受后的执行依据**：夜班开始时记录唯一任务 ID、Notion 来源、验收、预算/期限和本次决策日期，再执行。完成后保存报告与验证证据，并回填 Notion。
- 内容冲突、多个已选任务或选择范围不清时，先核实再执行。旧摘要、第三方引用、候选卡和默认预算不是新授权。
- GitHub 保留可公开的任务范围、代码与研究结论；账号信息、凭证、私人材料和完整对话不写入公开仓库。Notion 链接不改变页面的访问权限。

## 夜间执行步骤

默认北京时间每天 **22:00** 唤醒一次；实际运行依赖本机与 Codex 可用。先恢复 Hub 当前摘要，fetch 产品分支并读取最新主线，再读取 Notion 队列的选择。

1. 没有已选且已确认的任务：保持等待。同一状态不重复生成报告，不自行开展五条调研。
2. 恰好一个已选任务：读取整张卡，确认输入、验收、时限与费用边界；记录主线后，将卡标为执行中。多个已选或信息不足：保留待决定。
3. 在最新 `task/login-delegation` 基础上使用独立工作目录推进。检查已有执行记录；若上次已执行/完成，先读取结果，不能因重复唤醒重新派发。若仍执行中却无法确认是否停止，保持待核查。
4. 优先确定性脚本与已有资料；只有适合且在授权范围内的公开/合成批次才用已验证下游。真实批量调用依赖 E0 等相关问题已修复。不能用未接通的 TeleAgent、未知收费路径或额外模型分级来完成研究。
5. 达到验收、到达本晚时限或出现新的产品选择时收尾；不自动换另一张卡。交付包括 commit、实际测试/实验结果、未完成内容和下一条决策。
6. 验证通过的本任务改动可正常提交并非强制推送至产品分支，发布前检查范围与可公开性。远端有新改动时先保留并整合，不能覆盖用户提交；不自动合并独立历史到 main，也不默认升级运行服务。
7. Notion 回填结论、证据链接与状态：有交付待用户看则待验收；需新决定则待决策；完成并已被接受才已完成。用户白天确认后再选下一项。

完成、发生可处理的失败或需要新决定时汇报；无新增选择或状态无变化时保持安静。单晚中断、预算结束与任务失败分别记录。夜班调度不保证全夜连续运行，也不为了用满额度制造工作。

## 次日交付格式

一页内回答：完成了什么、证据在哪里、哪些结论仍未知、是否值得继续、唯一要用户拍板的问题。研究数据与工程测试分开，历史结果不能写成本晚实测。
