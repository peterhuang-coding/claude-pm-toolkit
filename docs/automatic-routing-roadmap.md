# Task Router 自动路由首版升级路线

本文记录 2026-09-14 的产品收敛与实现待办。它是当前演进方向，不代表所有条目已经完成；实际可用范围仍以 README、任务契约和代码为准。

产品方向比较另见 [研究待办](product-research-backlog.md) 和 [Notion 决策入口](https://app.notion.com/p/3db3285284df811897cfc48b24565164)。用户白天选定唯一任务后按 [昼夜交接约定](day-night-workflow.md) 执行；本路线中的待办不会因夜间唤醒而自动全部启动。

## 产品目标

Task Router 是一个开源、可自部署的自动任务路由器：用户首次接入自己已有的 AI 资源后，日常只提交任务目标；系统在内部完成任务分级、最小上下文准备、执行器选择、执行与验收，只在授权失效、预算不足或结果无法判断时请求用户接管。

一句话定义：**接入你已有的 AI，让任务自动找到合适的执行方式。**

“一次接入”不是跨平台一次登录。各平台仍须分别完成正常授权，并在授权有效期内复用；登录失效时只修复对应资源。免费额度、订阅额度和消费者网页入口都不是永久能力承诺。

## 调研后的差异判断

账号聚合、兼容 API、额度看板、按成本或任务类型路由均已有开源实现。Task Router 不以“接了更多平台”作为核心差异，而是验证下面这条完整闭环：

```text
是否值得执行 → 任务分级 → 最小上下文 → 合格执行器 → 验收
              → 有界修正 / 回退 → 完整消耗与结果反馈
```

候选价值是“按合格交付计算完整成本”：把主代理打包、下游失败、验收、修正和返工一起计算，而不是只比较单次 Token 单价。这个价值尚需真实业务批次验证，不能预先宣称节省比例。

直接参考与可复用方向：

| 项目 | 已覆盖的方向 | Task Router 应聚焦的剩余问题 |
|---|---|---|
| [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) | CLI 账号接入、兼容 API、多账号调用 | 不重复建设大量平台协议，关注任务交付闭环 |
| [Quotio](https://github.com/nguyenphutrong/quotio) | macOS 账号、额度和请求看板 | 看板服务于任务异常接管，不以账号面板为主产品 |
| [OmniRoute](https://github.com/diegosouzapw/OmniRoute) | 免费额度目录、任务适配、成本/延迟/质量路由与回退 | 业务验收标准、返工成本和是否值得外派 |
| [RouteLLM](https://github.com/lm-sys/RouteLLM) | 强弱模型路由与评估 | 面向可验收业务批次，而不是只路由单轮请求 |
| [Langfuse](https://github.com/langfuse/langfuse) | Trace、用量、成本和评估基础设施 | 业务批次、选择理由和结果复用可向其输出 |

## 首版支持范围

先把三类任务做透：

| 任务类型 | 默认执行方式 | 验收方式 |
|---|---|---|
| 反馈分类 | 已验证 CLI 或官方兼容 API | 数量、输入 ID、标签、原文证据、调用者语义复核 |
| 字段提取 | 已验证 CLI 或官方兼容 API | JSON Schema、必填字段、来源定位、调用者语义复核 |
| 排序、去重、格式转换 | 确定性本地脚本 | 规则断言和输入输出一致性 |

复杂开放式调研、任意代码修改、机密材料和需要登录的网页操作不进入自动路由首版。通过主代理提交时，主代理可在内部生成分级标签；直接工作台提交先使用明确模板，不承诺任意自然语言任务都能被准确自动分级。

## 实施批次

### A：接得上、跑得稳

- [x] 单 WorkBuddy 文本委派与调用者验收。
- [x] 登录确认与实际可执行状态分离。
- [x] 提交幂等键；相同键和请求返回原任务，不重复入队。
- [x] 结果记录当前固定执行器的选择理由，不冒充多执行器路由。
- [ ] 定义统一 Adapter 接口：能力、探针、提交、状态、取消、结果和原生用量。
- [ ] 验证并接入一个官方兼容 API；记录认证、版本、模型、费用和失败行为。
- [ ] 注册有限的确定性本地脚本能力。
- [ ] 建立 feedback-classification 与 field-extraction Harness。
- [ ] 补数据库迁移说明、安装自检和开源许可证决策。

### B：系统自动替用户决定

- [ ] 打通 Rule Router 与实际 Adapter 执行，不再使用固定 WorkBuddy 旁路。
- [ ] 主代理提交时生成任务类型、难度、时限、质量和数据边界标签。
- [ ] 直接工作台提交限制为明确任务模板，未知任务不猜测。
- [ ] 增加 schema、输入 ID、标签、字段和原文证据校验。
- [ ] 同一业务批次默认最多两次下游 Attempt：首次 + 一次修正或换执行器。
- [ ] 所有候选不可用时，按调用上下文返回主代理或进入待处理；独立后台不假装主代理已接管。
- [ ] 看板展示分级、路由理由、执行器、验收、Attempt 和原生用量。

A 与 B 都完成后，才能对外称为“自动路由首版”。只有 A 时仍是多执行器接入与任务委派底座。

### C：证明并扩大收益

- [ ] 登记主代理直做、本地脚本、复用、等待和下游路径，补齐业务统计分母。
- [ ] 用相同任务与验收器对比直做、WorkBuddy 和第二执行器。
- [ ] 接入有来源和更新时间的额度/重置快照，再做截止时间排队。
- [ ] 对公开网页采集保存来源快照，只在内容变化时触发提取。
- [ ] 结果部分失败时只修失败条目；有关联依赖时重验相关集合。
- [ ] 单机稳定后再增加 Mac mini 协调器与 MBP 按需 Worker。

## 自动链路的硬边界

- 默认不调用额外付费模型做任务分类；先使用主代理判断和确定性规则。
- 未知费用、余额或额度不等于免费、零或无限；不能进入无法守住预算的自动路径。
- 提供幂等键并不证明外部执行已停止。无法查询外部状态时仍须进入待核查，不能盲目换平台。
- JSON 合法、HTTP 200 或返回了文本都不等于业务完成；没有语义验收时保持 verifying。
- 免费额度不是任务来源，不为消耗赠送额度制造工作。
- Computer Use 只作为以后无结构化入口的低频候选，不用于绕过访问控制、付费或限流。

## 首版验收

- [ ] 至少两个 AI 执行器通过真实探针和同一任务模板验收。
- [ ] 路由结果改变实际执行者，并保存候选、排除原因和选择理由。
- [ ] 一条受支持路径从提交到合格交付无需用户手动选择执行器。
- [ ] 相同业务请求重试不产生第二个本地任务或第二次已确认派发。
- [ ] 登录失效、额度不足、执行失败和验收失败均不无声进入收费路径。
- [ ] 每批任务能回答执行者、上下文、Harness、尝试、验收和已知消耗。
- [ ] 干净环境能安装、启动、自检并跑通合成示例。

成功指标先建立基线：首次接入到首个合格任务的时间、受支持任务的无人干预交付率、每批人工介入次数、按时合格率、完整可比成本。没有直做基线和用量覆盖率时，不显示总体节省百分比。

## 本次明确不做

- 跨平台一次登录或永久有效授权。
- 同时接入十几个平台来制造覆盖面。
- 无限重试，或切换执行器后重置尝试次数。
- 未授权收费回退、自动绕过额度和消费者网页限制。
- 通用聊天助手、复杂 DAG 编辑器、企业多租户和学习型 Router。
- 在没有稳定任务模板和业务样本前，建设大而全的成本中心。
