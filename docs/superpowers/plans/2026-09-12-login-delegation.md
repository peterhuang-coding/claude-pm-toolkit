# 登录工作台与本地 Subagent API

用户已明确两层产品方向：集中打开 10 个平台供本人登录；主模型通过统一接口把简单任务交给下游。沿用本地 FastAPI、SQLite、任务状态机与 HTML，不新建云服务或凭证池。

1. 新增 10 个网页登录候选，另列 WorkBuddy 客户端。持久化本人标记的登录状态；自动调用状态仅根据客户端实测更新，浏览器 cookie 不进入工作台。
2. 新增 `/api/subagents` 提交、查询、取消、验收接口，持久化任务与最小输入包。仅简单、不急、非机密的文本任务；复杂/紧急/本地限定任务交回主模型。支持生成代码片段/测试草稿，项目修改仍由主模型完成。
3. 实现 WorkBuddy 随包 CLI 适配器：stdin 输入，工具/MCP 关闭，产品身份校验，超时/取消清理子进程，单客户端串行，失败不收费回退。首次显式连通探针通过后才接普通任务。
4. 调用成功先进入待验收；保存输出、模型、原生用量、耗时。主模型验收通过后完成。服务重启将未完成的客户端任务停为失败，避免自动重复消耗。
5. 登录与派发工作台显示真实状态、任务和结果；一次打开 10 页有拦截提示和逐页入口。新写接口限本地 JSON 客户端调用，并检查 Origin 与自定义请求头。
6. 测试：候选登录标记不能解锁路由；复杂/敏感任务拒绝；成功→待验收→完成；失败/取消/重启无静默重复；真实 WorkBuddy 合成批次验收；浏览器交互验证。修复失效 skill 链接到本仓库。

首版不会宣称 10 个平台已接通，也不假定网页登录自动授权 CLI。平台登录/验证码由用户完成后才能继续对应接入。模型选择首版沿用平台自己的自动选择，记录实际模型；有多个通过相同验收的选项后再按质量、剩余额度、耗时排序。
